# Prefab Deploy

Prefab Deploy 是 Minecraft 1.21.1 的预制建筑 Mod。玩家用建筑部署工具选择建筑、查看预览并部署。服务器管理建筑数据包。单人玩家和局域网主机还可以读取本地蓝图。

当前版本：**0.1.2**。需要 **Java 21** 和 **NeoForge 21.1.248 或更高的 1.21.1 版本**。使用建筑功能时，客户端和服务器安装同一版本。许可：[MPL-2.0](LICENSE)。

本模组由AI生成。使用时默认使用者知晓可能存在的稳定性或兼容性问题。

## 安装

从 [0.1.2 发布页](https://github.com/wuhanhao456/prefabdeploy/releases/tag/v0.1.2) 下载安装包。发布页同时提供源码和 SHA-256 清单。

将 `prefabdeploy-0.1.2.jar` 放入实例的 `mods/`。删除同一 Mod 的旧版 JAR。正式版不包含测试建筑。

客户端额外安装本 Mod 时，请下载 [客户端可选安装构建](https://github.com/wuhanhao456/prefabdeploy/releases/download/v0.1.2/prefabdeploy-0.1.2-client-optional.zip)，解压后使用其中的 JAR。连接未安装 Prefab Deploy 的服务器时，自动停用建筑库、预览和定位，并隐藏本 Mod 的创造物品。保存的快捷栏在该连接中跳过这些物品，原快捷栏文件保留。进入单人世界或连接已安装本 Mod 的服务器后恢复功能。客户端的其他 Mod 仍须与服务器兼容。该构建沿用 0.1.2 版本号；原发布页单独提供的旧 JAR 不包含此改动。构建与验证结果见[客户端可选安装验证](docs/TESTING-CLIENT-OPTIONAL.md)。

## 合成配方

建筑部署工具：2 个铁锭、1 张纸、1 个指南针、1 个红石粉。产出 1 个工具。

```text
铁锭     纸       铁锭
空       指南针   空
空       红石粉   空
```

位置信标：3 个紫水晶碎片、1 个萤石、1 个红石粉。产出 3 个信标。

```text
空           紫水晶碎片   空
紫水晶碎片   萤石         紫水晶碎片
空           红石粉       空
```

获得纸或紫水晶碎片后，配方会进入配方书。

## 使用

1. 合成建筑部署工具，或从创造模式的“预制建筑”标签页取出工具。
2. 持工具右键打开建筑库。选择建筑。拖动右侧预览可旋转，滚轮可缩放。
3. 选择“准星定位”。按 `R` 顺时针旋转 90°。
4. 对着预览外框内右键，固定位置并等待验证。验证通过后，再对外框内右键部署。
5. 对外框外右键取消定位。持工具或信标时，`Shift+右键` 可向任意方向取消。施工开始后不能取消。

预览外框内的门窗和空隙也算命中。预览加载期间不接受普通右键确认。黄色表示等待验证，绿色表示通过，红色表示失败。验证失败时，对外框内右键可重新定位。

“三点信标定位”使用真实的位置信标。依次放置 A、B、C。三点必须同高。B 指定正 X 方向，C 指定正 Z 方向。A 到 B 的边界距离等于建筑宽度。A 到 C 的边界距离等于建筑深度。

持信标对方块右键可常规放置。对空气右键可浮空放置。`Shift+滚轮` 调整浮空距离。放完三点后换回工具，仍需两次右键确认。三点尚未放完时，换回工具右键会取消定位。

生存模式按建筑定义收取费用。创造模式免除费用，但仍检查规则和位置权限。部署成功后移除定位信标，并返还实际消耗的信标。取消定位后，已放置的信标可手动拆回。

## 本地蓝图

在建筑库点击“打开蓝图文件夹”。将文件放入实例目录的 `prefabdeploy/blueprints/`。重新打开建筑库后读取新增或修改的文件。子目录也会读取。

支持 `.litematic` 格式版本 5–7 和原版结构 `.nbt`。Create 文件必须符合原版结构 NBT 格式。文件必须使用 Minecraft 1.21.1 的 DataVersion 3955。本版本不支持 `.schem`，也不转换旧版蓝图。

本地建筑默认使用文件名作为名称。参考层为最低层。空气会覆盖原方块。生存模式自动计算建筑材料。地下参考层、手动费用和规则可通过数据包或 KubeJS 设置。

本地导入仅向单人玩家或局域网主机开放。局域网加入者看不到主机的本地建筑。连接专用服务器时，文件夹按钮禁用。本地文件不会上传到服务器。服务器建筑通过数据包提供。

## 服务器热加载

将建筑数据包放入世界的 `datapacks/`。管理员在游戏中执行 `/prefab reload`。服务器控制台执行 `prefab reload`。

该命令需要权限等级 2。它发现新增数据包，并重读建筑定义、蓝图、费用和条件。KubeJS 注册事件会重新应用。新目录供后续选择使用。活动定位和部署保留原快照。

命令显示开始、完成或失败状态。完成时显示建筑数量和不可用数量。坏蓝图会成为不可用条目，不阻止其他建筑读取。失败细节写入服务器日志。重载期间不能再次启动同一命令。

单人世界或局域网主机执行该命令时，也会刷新本地蓝图。它不负责重读服务器 TOML 配置。

## 从源码构建

安装 Java 21。Windows 在 PowerShell 7 中执行：

```powershell
.\Build.ps1 -CacheRoot C:/work/prefabdeploy-cache -Task @('jar', 'sourcesJar')
```

构建缓存必须位于本地磁盘。脚本支持 UNC 工作区。JAR 会复制到 `dist/`。Linux 和 macOS 执行：

```sh
./gradlew jar sourcesJar
```

首次构建需要联网下载开发依赖。测试命令和打包方法见验证文档。默认位置上限为 100,000，包含明确覆盖的空气。部署任务共用每 Tick 2 ms 的软预算和 512 次操作上限。
