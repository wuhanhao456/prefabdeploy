# Prefab Deploy

[中文](README.md) | [English](README.en.md)

Prefab Deploy 是 Minecraft 1.21.1 的预制建筑 Mod。玩家用建筑建造工具选择建筑，查看预览后确认建造。服务器管理建筑数据包。单人玩家和局域网主机还可以读取本地蓝图。

当前版本：**0.1.3**。需要 **Java 21** 和 **NeoForge 21.1.248 或更高的 1.21.1 版本**。使用建筑功能时，客户端和服务器安装同一版本。许可：[MPL-2.0](LICENSE)。

本模组由 AI 生成。使用时默认使用者知晓可能存在的稳定性或兼容性问题。

下载 [0.1.3 安装包](https://github.com/wuhanhao456/prefabdeploy/releases/download/v0.1.3/prefabdeploy-0.1.3.zip)，将包内 `prefabdeploy-0.1.3.jar` 放入客户端和服务器的 `mods/`，同一实例只保留一个 Prefab Deploy JAR。正式 JAR 不包含测试建筑。完整源码、源码 JAR 和校验清单见[发布页](https://github.com/wuhanhao456/prefabdeploy/releases/tag/v0.1.3)。

## 合成配方

建筑建造工具：2 个铁锭、1 张纸、1 个指南针、1 个红石粉。产出 1 个工具。

```text
铁锭     纸       铁锭
空       指南针   空
空       红石粉   空
```

位置信标：3 个紫水晶碎片、1 个萤石、1 个红石粉。产出 3 个信标。

```text
空           紫水晶碎片   空
紫水晶碎片   萤石         紫水晶碎片
空           红石粉       空
```

获得纸或紫水晶碎片后，配方会进入配方书。

## 使用

1. 合成建筑建造工具，或从创造模式的“预制建筑”标签页取出工具。
2. 持工具右键打开建筑库。选择建筑。拖动右侧预览可旋转，滚轮可缩放。
3. 选择“准星定位”。按 `R` 顺时针旋转 90°。
4. 对着预览外框内右键，固定位置并等待验证。验证通过后，再对外框内右键建造。
5. 对外框外右键取消定位。持工具或信标时，`Shift+右键` 可向任意方向取消。施工开始后不能取消。

预览外框内的门窗和空隙也算命中。预览加载期间不接受普通右键确认。黄色表示等待验证，绿色表示通过，红色表示失败。验证失败时，对外框内右键可重新定位。

“三点信标定位”使用真实的位置信标。依次放置 A、B、C。三点必须同高。B 指定正 X 方向，C 指定正 Z 方向。A 到 B 的边界距离等于建筑宽度。A 到 C 的边界距离等于建筑深度。

持信标对方块右键可常规放置。对空气右键可浮空放置。`Shift+滚轮` 调整浮空距离。放完三点后换回工具，仍需两次右键确认。三点尚未放完时，换回工具右键会取消定位。

生存模式按建筑定义收取费用。创造模式无需消耗资源或支付其他费用，但仍检查规则和位置权限。建造成功后移除位置信标，并返还实际消耗的信标。取消定位后，已放置的信标可手动拆回。

空闲时，持建筑建造工具对容器 `Shift+右键` 绑定材料来源。物品提示显示灰色操作说明，绑定后显示坐标和维度。每把工具保存自己的绑定。空闲时对空气 `Shift+右键` 清除绑定；定位期间仍用于取消定位。支持原版箱子、木桶、精妙储存和 AE2 终端或接口连接的整个 ME 网络。

物品优先从工具绑定的容器或 ME 网络扣取，再从玩家库存、随身精妙背包、当前绑定的超越维度主网络补足。同维度且来源区块已加载时可以远程使用，不会强制加载来源。来源不可用时提示原因并使用其他来源。数量可以跨来源合并。自动材料中的水免费。自动岩浆先消耗岩浆桶，剩余格数从超越维度网络扣取每格 1000 mB 岩浆。手动桶费用仍按物品收费。已有建筑 `cost` 无需修改。支持版本和恢复方式见[资源兼容](docs/RESOURCE-COMPAT.md)。

连接未安装 Prefab Deploy 的服务器时，客户端停用建筑库、预览和定位，并隐藏本 Mod 的创造物品。返回单人世界或支持服务器后恢复功能。此前的连接测试见[客户端可选安装验证](docs/TESTING-CLIENT-OPTIONAL.md)。

## 本地蓝图

在建筑库点击“打开蓝图文件夹”。将文件放入实例目录的 `prefabdeploy/blueprints/`。重新打开建筑库后读取新增或修改的文件。子目录也会读取。

支持 `.litematic` 格式版本 5–7 和原版结构 `.nbt`。Create 文件必须符合原版结构 NBT 格式。文件必须使用 Minecraft 1.21.1 的 DataVersion 3955。本版本不支持 `.schem`，也不转换旧版蓝图。

本地建筑默认使用文件名作为名称。参考层为最低层。空气会覆盖原方块。生存模式自动计算建筑材料。有地下结构时，可通过数据包或 KubeJS 调整参考层。手动费用和规则也可通过这些接口配置。

本地导入仅向单人玩家或局域网主机开放。局域网加入者看不到主机的本地建筑。连接专用服务器时，文件夹按钮禁用。本地文件不会上传到服务器。服务器建筑通过数据包提供。

## 服务器热加载

将建筑数据包放入世界的 `datapacks/`。管理员在游戏中执行 `/prefab reload`。服务器控制台执行 `prefab reload`。

该命令需要权限等级 2。它发现新增数据包，并重读建筑定义、蓝图、费用和条件。KubeJS 注册事件会重新应用。新目录供后续选择使用。活动定位和建造保留原快照。

命令显示开始、完成或失败状态。完成时显示建筑数量和不可用数量。坏蓝图会成为不可用条目，不阻止其他建筑读取。失败细节写入服务器日志。重载期间不能再次启动同一命令。

单人世界或局域网主机执行该命令时，也会刷新本地蓝图。它不负责重读服务器 TOML 配置。

## 从源码构建

安装 Java 21。Windows 在 PowerShell 7 中执行：

```powershell
.\Build.ps1 -CacheRoot C:/work/prefabdeploy-cache -Task @('jar', 'sourcesJar')
```

构建缓存必须位于本地磁盘。脚本支持 UNC 工作区。JAR 会复制到 `dist/`。Linux 和 macOS 执行：

```sh
./gradlew jar sourcesJar
```

首次构建需要联网下载开发依赖。测试命令和打包方法见验证文档。默认位置上限为 100,000，包含明确覆盖的空气。建造任务共用每 Tick 2 ms 的软预算和 512 次操作上限。
