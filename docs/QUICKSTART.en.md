# Prefab Deploy 0.1.3

[Full English README](../README.en.md) | [中文 README](../README.md)

Prefab Deploy lets players preview and build saved buildings. It requires Minecraft 1.21.1, NeoForge 21.1.248 or later for 1.21.1, and Java 21. Install the same mod version on the client and server to use building features.

This mod was generated by AI. By using it, you acknowledge that stability or compatibility issues may occur.

Download the [resource compatibility build](https://github.com/wuhanhao456/prefabdeploy/releases/download/v0.1.3/prefabdeploy-0.1.3.zip). Extract the ZIP and put `prefabdeploy-0.1.3.jar` in `mods/`. Keep only one Prefab Deploy JAR in each instance. Version 0.1.3 includes container binding and the previous resource compatibility features.

You can also join servers without Prefab Deploy. On those servers, the client disables building features and hides Prefab Deploy items in the creative inventory. Saved hotbars skip these items without changing the saved file. Features return in singleplayer or on a server with Prefab Deploy. Other client mods must also be compatible with the server. Earlier connection tests are recorded in [client optional installation verification](TESTING-CLIENT-OPTIONAL.md). Test coverage for this build is recorded in [resource compatibility verification](TESTING-RESOURCES.md). These records are in Chinese.

## Use

1. Craft a Building Tool or take one from the **Prefab Deploy** creative tab.
2. Hold the tool and right-click to open the library, then select a building and placement mode. Drag the preview to rotate it, or scroll to zoom.
3. For **Crosshair placement**, press `R` to rotate clockwise by 90°.
4. Right-click inside the preview frame to fix the position. Once validation passes, right-click inside the frame again to build.
5. Right-click outside the frame to cancel placement. While holding the tool or a beacon, use `Shift+right-click` to cancel in any direction.

Empty space inside the frame also counts as a target. Normal right-click confirmation is unavailable while the preview loads. Yellow means validation is pending, green means it passed and red means it failed. If validation fails, right-click inside the frame to reposition the building. Construction cannot be cancelled after it starts.

For **Three-beacon placement**, place Positioning Beacons A, B and C in that order at the same height. B defines positive X, and C defines positive Z. The A–B boundary distance must equal the building width; the A–C boundary distance must equal its depth. Switch back to the Building Tool and confirm twice. A tool right-click before all three beacons are placed cancels placement.

Hold a beacon and right-click a block to place it normally, or right-click in the air to place a floating beacon. Use `Shift+scroll` to adjust its distance. Successful construction returns only the beacons actually consumed. After cancelling placement, you can break the placed beacons to recover them.

Survival mode charges the costs set in the building definition. Creative mode requires no resources or other payments, but rules and position permissions still apply.

## Import local blueprints

Select **Open blueprint folder** and put `.litematic` or vanilla structure `.nbt` files in `<instance>/prefabdeploy/blueprints/`. Reopen the library to load changes. Subfolders are supported.

Litematic versions 5–7 are supported. All files must use Minecraft 1.21.1 DataVersion 3955. Create NBT files must follow the vanilla structure format. `.schem` and conversion of older blueprints are not supported.

Local buildings use the filename as their default name. The ground reference is the lowest layer, with index 0. Air overwrites existing blocks. In survival mode, local buildings use automatically calculated material costs.

Local import is available only to the singleplayer or LAN host. LAN guests cannot access the host's local buildings. The folder button is disabled on dedicated servers, and local files are not uploaded. Servers provide buildings through datapacks. The release JAR contains no test buildings.

While idle, Shift+right-click a container with the Building Tool to bind a material source. The gray item tooltip shows its coordinates and dimension. Each tool has its own binding. Shift+right-click air while idle clears it; during placement this gesture still cancels placement. Vanilla chests and barrels, Sophisticated Storage, and whole AE2 networks through terminals or interfaces are supported.

Item costs use the bound source first, then the player inventory, carried Sophisticated Backpacks, and the player's current Beyond Dimensions primary network. The bound source must be in the same dimension and already loaded. Unavailable sources fall back with a notice. Quantities can be combined. Water has no automatic material cost. Lava buckets pay first, then Beyond Dimensions supplies 1000 mB per remaining lava block. Manual bucket costs require items. Backpack tanks do not provide fluid. See [supported versions](RESOURCE-COMPAT.md). Binding is available in version 0.1.3.

Supported versions and recovery procedures are listed in [resource compatibility](RESOURCE-COMPAT.md).

## Recipes and server reload

The Building Tool requires 2 iron ingots, 1 paper, 1 compass and 1 redstone dust. Put the iron ingots and paper in the top row, with paper in the middle. Put the compass in the center and redstone below it. The recipe makes one tool.

The Positioning Beacon requires 3 amethyst shards, 1 glowstone and 1 redstone dust. Put glowstone in the center, with amethyst above it and on both sides. Put redstone below it. The recipe makes three beacons. Obtaining paper or an amethyst shard unlocks the corresponding recipe in the recipe book.

Put building datapacks in the world's `datapacks/` folder. Run `/prefab reload` in game, or `prefab reload` in the server console. The command requires permission level 2. It discovers new datapacks and reloads building definitions, blueprints, costs and rules, then reapplies KubeJS registry events. It reports the building count and the number of unavailable entries. Active placement sessions and construction tasks keep their original snapshots. On a singleplayer or LAN host, the command also refreshes local blueprints. It does not reload server TOML configuration.
