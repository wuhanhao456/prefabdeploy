# Prefab Deploy 管理员说明

本 Mod 的建造由服务器完成。每个任务固定源数据、世界变换、玩家、费用和生成实体 UUID，因此重载建筑库不会改变已启动任务。任务锁定涉及的**完整区块**，避免旁侧容器和 Tick 在恢复过程中改变快照对应的世界状态。

当前版本为 0.1.3，需要 Minecraft 1.21.1、Java 21 和 NeoForge 21.1.248 或更高的 1.21.1 版本。已有验证的范围和限制见[0.1.3 验证记录](TESTING-0.1.3.md)和[资源兼容验证](TESTING-RESOURCES.md)。部分手工交互组合仍待检查，历史记录单独保留。

<a id="011-操作与费用"></a>

## 操作与费用

创造模式可从“预制建筑”标签页获得建筑建造工具和位置信标，原工具标签页入口保留。`R` 顺时针旋转 90°。定位时，主手持工具或信标并使用 `Shift+右键` 可取消定位，朝向方块或空气均可。施工开始后不能取消。`Esc` 使用 Minecraft 默认行为。持信标对方块右键可常规放置，对空气右键可浮空放置，`Shift+滚轮` 调整距离。

服务器在实际建造任务报价时判定创造模式，保存 `price.creativeExempt` 与零费用报价。创造模式无需消耗资源，也免除 XP、ViScriptShop 和自定义费用，因此不调用费用提供者的报价、预留、结算和费用返还回调。解锁、脚本建造规则、领地权限、世界限制和恢复保护仍会检查。预览报价仅用于显示；二次确认后的实际任务会重新检查并固定自己的报价。

固定报价后切换模式不改变该任务费用。旧日志没有豁免字段时保留原报价，不根据当前模式重新计算。信标放置时记录实际减少的物品数量，任务日志保存 `beaconRefundCount`，成功只返还该数量。三枚均为创造放置时返还为零；混合模式放置只返还生存模式消耗部分。旧日志没有数量字段时沿用旧任务的信标数量与幂等回收凭据。

客户端语言资源位于 `assets/prefabdeploy/lang/en_us.json` 和 `zh_cn.json`，可通过资源包覆盖。费用、规则摘要和原生错误由服务器发送结构化翻译字段；名称、分类、作者条件说明和脚本普通文字保持原样。诊断日志和管理员审计仍保留原始数据，翻译不参与权限判定。

## 配置

第一次启动世界生成 `<world>/serverconfig/prefabdeploy-server.toml`。可将 `examples/prefabdeploy-server.toml` 放入实例的 `defaultconfigs/`，作为新世界默认配置。建议停止服务器后修改限制，然后重启。

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `limits.maxPositions` | 100000 | 实际处理的方块位置，空气也计入；最高可设 500 万 |
| `limits.maxChunks` | 256 | 单任务涉及区块总数，含实体、源 Tick、信标 |
| `limits.operationsPerTick` | 512 | 全服所有任务共享的操作上限 |
| `limits.tickBudgetMs` | 2.0 | 全局软时间预算，单次操作不能被中途打断 |
| `limits.placementDistance` | 32 | 准星和浮空信标距离限制，最大 128 |
| `limits.maxNbtBytes` | 67108864 | 压缩源文件及解压 NBT 读取上限 |
| `security.protectedBlocks` | 基岩、末地传送门及框架 | 禁止覆盖的现有方块 |
| `security.forbiddenContent` | 命令方块、结构方块、拼图方块 | 禁止建造的蓝图方块 |

数据包标签 `prefabdeploy:protected` 也禁止覆盖。将 `data/prefabdeploy/tags/block/protected.json` 加入数据包可以追加其他受保护方块。命令方块矿车和玩家实体禁止从蓝图生成。

额外硬限制为最多 4096 个实体及乘客、16 层乘客嵌套、128 MiB 原世界快照和 192 MiB 恢复记录估算大小；超出时在扣费前拒绝。读取恢复日志上限为 256 MiB。

所有实际修改位置、信标、实体/乘客位置和源 Tick 目标都检查高度、世界边界、保护方块、出生点保护和 FTB Chunks 编辑权限。加载已有区块时使用异步读取；磁盘没有完整已生成区块会拒绝，请先探索。跨维度通过规则决定，不限定主世界。

## 命令

除 `/prefab claim` 外，下列管理命令需要权限等级 2。

| 命令 | 用途 |
| --- | --- |
| `/prefab reload` | 重新加载数据包、验证源文件、生成解析及材料缓存 |
| `/prefab tasks` | 当前任务 UUID、阶段、进度和错误 |
| `/prefab metrics` | 建造调度器耗时 p95 与样本数 |
| `/prefab audit <UUID>` | 从持久化日志读取状态、玩家、建筑、报价和错误 |
| `/prefab receipt <在线玩家> <UUID>` | 查看玩家 NBT 中的完整交易凭据 |
| `/prefab recover <UUID>` | 重试处于 HELD 的恢复/结算任务 |
| `/prefab reconcile_currency <在线玩家> <UUID> <still_owed>` | 记录未知货币交易仍应退款的金额；之后使用 recover |
| `/prefab grant <玩家或团队UUID> <flag>` | 授予解锁标记 |
| `/prefab revoke <玩家或团队UUID> <flag>` | 撤销解锁标记 |
| `/prefab claim` | 玩家领取库存放不下的返还物品和信标 |

`still_owed` 是**仍应退回的金额**，不是当前余额，也不是重新扣款指令。核对商店余额、凭据 `moneyBefore` / `moneyPaidAmount` / `moneyRefundBefore` 后再填写。Mod 不会对未知结果自动重复支付。

<a id="部署事务和恢复"></a>

## 建造事务和恢复

正常流程：准备已生成区块 → 临时锁定 → 分批完整验证与快照 → 原世界基线落盘 → PREPARED 恢复日志落盘 → 预留费用及玩家文件落盘 → 分批方块、NBT、实体和 Tick → 新世界落盘 → COMMITTED 日志落盘 → 结算、回收信标和 DONE 日志 → 解锁 → 分批普通邻居更新。

恢复日志位于 `<world>/prefabdeploy/transactions/<UUID>.journal`，带校验和并通过文件强制刷新及原子替换写入。玩家物品、XP、ViScriptShop 原生余额和凭据一起写入同一个 `playerdata/<UUID>.dat`。单人游戏读取此文件中的事务版本，避免 `level.dat` 中旧玩家状态覆盖扣款记录。

- 启动发现 PREPARED：恢复原方块、完整方块实体及区块相关 Tick，清除预先记录身份的本任务实体，再返还费用。
- 启动发现 COMMITTED：保留已持久化的建筑，幂等完成结算及信标回收。
- REFUND：原世界已经恢复，等待玩家上线返还费用；恢复完成后区域可以解锁。
- DONE：只保留精简审计信息，不存可供玩家 Undo 的快照。
- 恢复或结算失败：进入 HELD，保留日志和区域锁；修复原因后执行 recover。日志损坏时拒绝启动世界，避免带着无法恢复的半成品继续运行。

玩家离线时，费用返还等待上线。库存空间不足时，物品保存在持久化凭据或邮箱中，登录或执行 `/prefab claim` 后领取，不会丢到地面。重复结算、返还和领取不会重复给付。取消定位或退出游戏不会撤销已经开始的施工任务。

背包和网络的资源与事务凭据保存在同一个 SavedData 文件中。普通背包按内容 UUID 恢复。链接背包按共享组 UUID 恢复。网络按网络 ID 恢复。玩家更换背包或网络不会改变资源返还目标。

玩家文件先保存库存扣费与外部来源意图。各来源随后保存预留结果。玩家文件最后保存 `resourcesReady`。全部预留成功后才开始施工。

`/prefab receipt <在线玩家> <UUID>` 的 `externalReceipts` 列出原来源、文件路径、凭据状态和剩余 `escrow`。无法读取来源时，该记录显示 `error`。来源缺失、版本不支持、文件不一致、原存储空间不足或结果不确定时，任务进入 HELD。修复来源或腾出原存储空间后，执行 `/prefab recover <UUID>`，将外部资源返还到原存储。`/prefab claim` 只领取返还到玩家库存的物品和信标。

`REFUND_PENDING` 保留尚未退回的资源及其组件和数量。`UNCERTAIN` 表示来源 API 的结果无法确认。恢复流程不通过余额变化猜测扣费结果。

工具绑定的原版容器和精妙储存直接库存，将库存与凭据写入同一来源区块。双箱每半部分独立保存。更换同坐标容器不能接收旧容器的返还。AE2 和其他外部库存使用 `prefabdeploy/bound-resources/` 预写日志；完成凭据前刷新世界及 SavedData。重启时，未完成的第三方事务转为 `UNCERTAIN` 并进入 HELD，需要核对原网络和日志。不能仅通过重新供电或腾出空间认定未知扣取已经成功。来源暂时卸载、断电或已知容量不足的普通返还，可在原来源恢复后重试。绑定范围和版本见[资源兼容](RESOURCE-COMPAT.md)。

内存与文件不一致时，恢复流程拒绝重试。先停止服务器，再核对持久化记录。保留日志、玩家文件和相关 SavedData。不要删除凭据或只还原单个存储文件。备份和还原须使用同一停服时点的完整世界。文件路径见[资源兼容](RESOURCE-COMPAT.md#事务文件)。

请将整个世界一起备份，包括 `playerdata/`、`prefabdeploy/`、区块和实体数据。不要在任务进行时单独删除日志、手工替换玩家文件或移除提供资源或费用的联动模组。

## 运行边界

区域锁阻止常规放置、破坏、容器操作和直接 Level/LevelChunk 写入，暂停方块实体、随机 Tick、计划 Tick 与非玩家实体；邻接容器 Tick 也暂停。玩家进入待放置的实体碰撞区域会使任务恢复。模组绕过这些入口直接改内部容器、内存或外部数据库时，需要它自身的事务适配。

蓝图中的通用 NBT 可完整复制，但跨方块网络、模组专有坐标、多方块控制器和外部服务副作用不由通用 NBT 自动修复。作者可注册 `NbtTransformAdapter`；缺少专用适配时需要玩家重新连接网络。测试覆盖原版库存/告示牌/旗帜/装备实体及 FTB 模组方块；不能据此承诺所有机器都可完整迁移。

COMMITTED 后的邻居更新遵循正常 Minecraft 物理，沙子、流体、红石和模组机器可能继续变化；此时施工已经成功，没有主动 Undo。大型含大量复杂方块实体的蓝图，NBT 读取、单次区块序列化、玩家文件 fsync 或机器回调可能超过 2 ms 软预算。性能记录同时给出 p95 和最大值，不能将软预算理解为每 Tick 硬上限。

客户端解析和压缩在后台线程，网格按分区缓存并分批上传 GPU；文件解析/缓存也在后台线程，世界读写位于服务器线程。默认客户端最多缓存 8 个建筑网格，服务器最多缓存 32 份 / 128 MiB 压缩预览。网络按 48 KiB 分片、全服每 Tick 最多 4 片发送，客户端限制 64 MiB 解压数据。

建筑目录分成估算不超过 192 KiB 的页面，单个条目超过该限制会报错；单消息估算上限 512 KiB、网络 NBT 读取上限 1 MiB。目录只包含可见条目。预览并不携带允许客户端写入世界的方块内容请求。

## 建筑热加载

服务器控制台执行 `prefab reload`。游戏内管理员执行 `/prefab reload`。需要权限等级 2。命令发现新增数据包，并重读建筑定义、蓝图、费用和规则。世界已禁用的数据包不会被自动启用。

完成时显示建筑总数和不可用数量。损坏定义会显示为不可用条目。全局重载失败时检查日志。命令未完成前不能再次启动重载。活动定位和建造保留原快照。新选择使用新定义。

单人玩家或局域网主机也可用该命令刷新本地蓝图。局域网加入者仍不能访问这些建筑。命令不重读服务器 TOML 配置。
