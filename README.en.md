# Prefab Deploy

[中文](README.md) | [English](README.en.md)

Prefab Deploy is a prefab building mod for Minecraft 1.21.1. Players use the Building Tool to select a building, preview it and start construction. Servers provide buildings through datapacks. Singleplayer and LAN hosts can also load local blueprints.

Current version: **0.1.4**. Requires **Java 21** and **NeoForge 21.1.248 or later for Minecraft 1.21.1**. Install the same mod version on the client and server to use building features. License: [MPL-2.0](LICENSE).

This mod was generated by AI. By using it, you acknowledge that stability or compatibility issues may occur.

## Installation

Download the [0.1.4 installation ZIP](https://github.com/wuhanhao456/prefabdeploy/releases/download/v0.1.4/prefabdeploy-0.1.4.zip) and put `prefabdeploy-0.1.4.jar` in the instance's `mods/` folder on both the client and server. Keep only one Prefab Deploy JAR in each instance. The [release page](https://github.com/wuhanhao456/prefabdeploy/releases/tag/v0.1.4) provides standalone JARs, source code and SHA-256 checksums. Earlier releases remain available; source builds are delivered in `dist/`.

Version 0.1.4 includes a dark chamber mob tower and a zombie spawner tower, enabled by default. Set `buildings.enableDefaultTestBuildings = false` in the server's `prefabdeploy-server.toml` and restart to disable the built-in buildings. Both are immediately unlocked and limited to the Overworld. The dark tower uses automatic material costs; the zombie tower uses a complete manual material list, replacing one spawner with 50 rotten flesh. External definitions with the same IDs are unaffected. Container binding and previous resource compatibility features remain available.

When you join a server without Prefab Deploy, the client disables the building library, previews and placement. The creative inventory hides this mod's items. Saved hotbars skip these items without changing the saved hotbar file. Building features return in singleplayer or on a server with Prefab Deploy. Other client mods must also be compatible with the server. Earlier connection tests are recorded in [client optional installation verification](docs/TESTING-CLIENT-OPTIONAL.md). Test coverage for this build is recorded in [resource compatibility verification](docs/TESTING-RESOURCES.md). These records are in Chinese.

## Crafting recipes

The Building Tool requires 2 iron ingots, 1 paper, 1 compass and 1 redstone dust. The recipe makes one tool.

```text
Iron ingot   Paper           Iron ingot
Empty        Compass         Empty
Empty        Redstone dust   Empty
```

The Positioning Beacon requires 3 amethyst shards, 1 glowstone and 1 redstone dust. The recipe makes three beacons.

```text
Empty            Amethyst shard   Empty
Amethyst shard   Glowstone        Amethyst shard
Empty            Redstone dust    Empty
```

Obtaining paper unlocks the tool recipe in the recipe book. Obtaining an amethyst shard unlocks the beacon recipe.

## Use

1. Craft a Building Tool or take one from the **Prefab Deploy** creative tab.
2. Hold the tool and right-click to open the library, then select a building. Drag the preview on the right to rotate it, or scroll to zoom.
3. Select **Crosshair placement**. Press `R` to rotate clockwise by 90°.
4. Right-click inside the preview frame to fix the position and wait for validation. Once validation passes, right-click inside the frame again to build.
5. Right-click outside the frame to cancel placement. While holding the tool or a beacon, use `Shift+right-click` to cancel in any direction. Construction cannot be cancelled after it starts.

Doors, windows and empty space inside the preview frame also count as targets. Normal right-click confirmation is unavailable while the preview loads. Yellow means validation is pending, green means it passed and red means it failed. If validation fails, right-click inside the frame to reposition the building.

**Three-beacon placement** uses actual Positioning Beacons. Place A, B and C in that order at the same height. B defines the positive X direction, and C defines the positive Z direction. The boundary distance from A to B must equal the building width; the boundary distance from A to C must equal its depth.

Hold a beacon and right-click a block to place it normally, or right-click in the air to place a floating beacon. Use `Shift+scroll` to adjust the floating distance. After placing all three beacons, switch back to the Building Tool and confirm twice. If you right-click with the tool before placing all three beacons, placement is cancelled.

Survival mode charges the costs set in the building definition. Creative mode requires no resources or other payments, but rules and position permissions still apply. When construction succeeds, the positioning beacons are removed and only those actually consumed are returned. After cancelling placement, you can break the placed beacons to recover them.

While idle, hold the Building Tool and Shift+right-click a container to bind it. The gray item tooltip shows the binding hint and, after binding, its coordinates and dimension. Each tool keeps its own binding. Shift+right-click air while idle to clear it; during placement the same gesture still cancels placement. Supported sources include vanilla chests and barrels, Sophisticated Storage, and the whole ME network reached through an AE2 terminal or interface.

Item costs use the bound container or ME network first, then the player inventory, carried Sophisticated Backpacks, and the player's current Beyond Dimensions primary network. Remote use requires the same dimension and an already loaded source chunk. Unavailable bindings display a reason and fall back to other sources. Quantities can be combined. Water has no automatic material cost. Lava buckets pay first; each remaining lava block uses 1000 mB from Beyond Dimensions. Manual bucket costs still require items. Existing `cost` definitions need no changes. See [resource compatibility](docs/RESOURCE-COMPAT.md) for supported versions and recovery. Container binding is included in version 0.1.3.

## Local blueprints

Select **Open blueprint folder** in the library and put files in the instance's `prefabdeploy/blueprints/` folder. Reopen the library to load new or changed files. Subfolders are also read.

Supported formats are `.litematic` versions 5–7 and vanilla structure `.nbt`. Create files must follow the vanilla structure NBT format. All files must use Minecraft 1.21.1 DataVersion 3955. This version does not support `.schem` or convert older blueprints.

Local buildings use the filename as their default name and the lowest layer as their ground reference. Air overwrites existing blocks. In survival mode, local buildings use automatically calculated material costs. For buildings with underground sections, use datapacks or KubeJS to adjust the ground reference. You can also use these interfaces to set manual costs and rules.

Loose blueprint import is available only to the singleplayer or LAN host. LAN guests cannot see those loose blueprints. The folder button is disabled on dedicated servers, and local files are not uploaded to the server.

The same folder also accepts building datapacks as ZIP files or unpacked directories placed directly inside it. Each pack must contain `pack.mcmeta` at its root. Run `/prefab reload` to load definitions, rules and costs. NBT files inside datapack directories are excluded from loose blueprint import. Datapacks are read from the running server or LAN host and shared with its players; singleplayer uses the local instance.

## Server reload

Put building datapacks in the world's `datapacks/` folder or the server instance's `prefabdeploy/blueprints/` folder. Run `/prefab reload` in game as an administrator, or `prefab reload` in the server console.

The command requires permission level 2. It discovers new datapacks and reloads building definitions, blueprints, costs and rules. KubeJS registry events are applied again. Later selections use the new catalog; active placement sessions and construction tasks keep their original snapshots.

The command reports when reloading starts, completes or fails. On completion, it reports the building count and the number of unavailable entries. Invalid blueprints become unavailable entries without blocking other buildings. Details are written to the server log. Another reload cannot start while one is running.

In singleplayer or on a LAN host, the command also refreshes local blueprints. It does not reload server TOML configuration.

## Building from source

Install Java 21. On Windows, run this command in PowerShell 7:

```powershell
.\Build.ps1 -CacheRoot C:/work/prefabdeploy-cache -Task @('jar', 'sourcesJar')
```

The build cache must be on a local disk. The script supports UNC workspaces and copies JARs to `dist/`. On Linux or macOS, run:

```sh
./gradlew jar sourcesJar
```

The first build needs internet access to download development dependencies. Test commands and packaging procedures are in the verification records. The default position limit is 100,000, including air positions that explicitly overwrite blocks. All construction tasks share a soft budget of 2 ms and a limit of 512 operations per tick.
